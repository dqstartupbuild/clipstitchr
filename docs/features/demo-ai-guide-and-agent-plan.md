# Demo AI Guide And Agent Plan

This document is the production build plan for turning the shipped guided demo
recorder into an AI-assisted guide writer and, later, a guarded local browser
agent. It intentionally keeps the manual recorder as the stable default until
the AI and autonomous layers have enough safeguards.

## Current Status

Already implemented:

- `clipstitchr demo make` can create, save, reuse, and upload walkthrough
  guides.
- Guides are saved in `.clipstitchr/demo-guides/*.json`.
- The last used guide ID is saved in `.clipstitchr.yml`.
- Web, iOS, Android, and React Native recording paths can show the stepper and
  capture step timings.
- Web recordings also upload click and cursor timing metadata.
- `POST /api/cli/uploads/demo/complete` validates and stores `walkthrough`
  metadata in the media job input snapshot.
- AI-generated guide creation.
- A user-visible guide editor in the CLI.
- A dedicated `clipstitchr demo guide` command namespace.
- A downloadable agent instruction export.
- Local demo agent policy initialization and validation.
- Guarded `clipstitchr demo agent run --dry-run` with local screenshots,
  action logs, run summaries, and a deterministic policy-validated browser
  action loop.
- CLI-local observer, planner, validator, and executor tests, including
  Playwright fixture coverage for approved browser actions.
- CLI-local full-loop tests for safe multi-step guide flow, blocked observed
  page text, external navigation, disallowed routes, repeated page state, step
  timings, screenshots, auth walls, modal flows, long loading waits, 404 page
  states, and URL before/after action logging.
- Injectable planner seam and strict JSON planner-action parser for future LLM
  planning, with tests proving unsafe planner output is blocked before
  execution.
- Opt-in `--ai-planner` mode that calls `POST /api/cli/demo-agent/plan` for one
  model-proposed action at a time, after rate limiting and before local policy
  validation.
- Dedicated `CLI_DEMO_AGENT_PLANNER_MODEL_ID` support for model-backed browser
  planning, defaulting to `openai/gpt-5-mini`.
- CLI fallback from model-backed planning to the deterministic local planner
  after the first provider failure in a run.
- CLI fallback from model-backed planning to the deterministic local planner
  when the model repeats an already-attempted action.
- `clipstitchr demo auto` asks what the demo should show when `--goal` is not
  provided, then sends that goal into guide generation and planner prompts.
- CLI app context capture writes `.clipstitchr/app-context.json` during setup
  and AI demo phases, then sends capped route/workflow/input/button hints into
  guide generation and agent planning.
- Guarded local recording from an agent run with mandatory review before upload.
- Safe optional `walkthrough.agentRun` metadata parsing.
- OpenAI Computer Use driver for local visual browser control, selected through
  `demoAgent.driver` or `--driver openai-computer`.
- Dedicated CLI guide-writing model setting through `CLI_DEMO_GUIDE_MODEL_ID`,
  defaulting to `openai/gpt-5-mini`.

Not implemented yet:

- GUI smoke coverage for the recorded browser path.
- Production smoke coverage for model-backed planning.

## Product Decision

Phase 3 is the stable assisted layer. The AI writes a recording checklist, but
the user still records manually.

Phase 4, Full AI Agent, should be local-first and opt-in. The backend should not
remotely control a user's app. The CLI runs the browser agent on the user's
machine, applies strict guardrails before each action, stores local evidence,
and asks for user approval before upload.

ClipStitchr should use its own internal guide and policy format as the source
of truth. A downloadable agent skill can come later as an export format, but it
should not be the primary production dependency because outside agents do not
guarantee consistent action logs, safety checks, or upload metadata.

## Shared Contract

Every phase should use the same `DemoWalkthroughGuide` concept:

```json
{
  "version": 1,
  "id": "guide_abc123",
  "title": "ClipStitchr upload walkthrough",
  "goal": "Show the upload flow",
  "source": "ai-assisted",
  "productId": "product_123",
  "productName": "ClipStitchr",
  "appType": "web",
  "flowName": "Show the main workspace",
  "flowPath": "/dashboard",
  "steps": [
    {
      "id": "step-1",
      "label": "Open the dashboard"
    }
  ],
  "createdAt": "2026-07-06T00:00:00.000Z",
  "updatedAt": "2026-07-06T00:00:00.000Z"
}
```

Supported guide sources:

- `cli-template`: deterministic checklist made locally by the CLI.
- `ai-assisted`: checklist generated by ClipStitchr AI and approved by the
  user.
- `agent-authored`: checklist imported from or written by a local agent
  instruction workflow.

Upload metadata should keep using the existing `walkthrough` object:

```json
{
  "walkthrough": {
    "guide": {},
    "timings": [],
    "agentRun": {
      "id": "agent_run_abc123",
      "mode": "guided-browser",
      "actionLogObjectKey": "optional-future-r2-key"
    }
  }
}
```

`agentRun` should remain optional until Phase 4. The current backend reader
drops unknown keys, so storing agent run metadata requires an intentional reader
update and focused tests.

## Phase 3: AI-Assisted Script

### User Flow

1. User runs `clipstitchr demo guide generate`.
2. CLI asks for product, selected flow, target audience, and what the demo
   should show.
3. CLI sends a small request to ClipStitchr with route context and capped local
   app workflow hints.
4. Backend verifies the CLI session, product ownership, and rate limits.
5. Backend calls the writing provider with a strict JSON prompt.
6. Backend validates the returned guide shape and returns it to the CLI.
7. CLI shows the guide and asks whether to use it, edit it, regenerate it, or
   save without recording.
8. Accepted guide is saved to `.clipstitchr/demo-guides/*.json`.
9. `clipstitchr demo make --guide <id>` records with the same manual stepper
   that already works.

### CLI Commands

Add a dedicated guide namespace:

```bash
clipstitchr demo guide generate
clipstitchr demo guide list
clipstitchr demo guide show guide_123
clipstitchr demo guide edit guide_123
clipstitchr demo guide delete guide_123
clipstitchr demo guide export-instructions guide_123
```

`clipstitchr demo make` should stay simple. It can offer "Create an AI
walkthrough" in the existing guide prompt after Phase 3 is stable, but the
first implementation should keep AI generation behind the explicit
`demo guide generate` command.

### Backend API

Add:

```http
POST /api/cli/demo-guides/generate
```

Request:

```json
{
  "productId": "product_123",
  "appType": "web",
  "flowName": "Show the dashboard",
  "flowPath": "/dashboard",
  "goal": "Show the upload flow",
  "targetAudience": "busy founders recording product demos",
  "appContext": {
    "routes": [],
    "workflowHints": []
  },
  "stepCount": 5
}
```

Response:

```json
{
  "guide": {
    "version": 1,
    "id": "guide_abc123",
    "title": "Upload flow walkthrough",
    "goal": "Show the upload flow",
    "source": "ai-assisted",
    "steps": []
  },
  "providerModel": "openai/gpt-5-mini",
  "providerPredictionId": "prediction_123"
}
```

Implementation notes:

- Use `getCliSessionFromRequest` for bearer-token auth.
- Query the product by `productId` and session owner before any provider call.
- Consume a writing-provider rate limit before calling Replicate.
- Use the dedicated `CLI_DEMO_GUIDE_MODEL_ID` path through
  `createTextWritingPredictionInput`.
- Add one prompt file, one parser file, one route reader file, and focused
  tests for each. Do not place prompt construction and response parsing in the
  route handler.
- Limit generated guides to 3-8 steps in the first release. The upload reader
  already caps stored guide steps at 20, but the guide generator should be
  tighter.
- Generated steps must be labels only. Do not ask the AI to output browser
  selectors, passwords, secret values, or hidden implementation details in
  Phase 3.

### Rate Limits

Add a named limit instead of reusing a misleading Clipr label:

- `cliDemoGuideGenerate`: 20/hour/user, burst 5.
- `cliDemoGuideGenerateGlobal`: 1,000/hour, burst 200, sharded.
- Reuse the shared writing-provider global bucket so one user cannot drain the
  provider spend pool.

Update `docs/backend/rate-limits.md` with the API path, limits, environment
variables, and verification steps in the same change.

### AI Prompt Rules

The prompt must require:

- Return only JSON.
- Return one concise title, one plain-language goal, and 3-8 steps.
- Each step label should be an action the user can understand while recording.
- Prefer product-visible moments over implementation details.
- Include waiting steps only when the user explicitly mentions loading,
  generation, export, processing, or review.
- Never invent claims, stats, customer outcomes, pricing, or integrations.
- Never include passwords, API keys, payment changes, destructive actions, or
  private customer data.
- Keep auth steps generic, such as "Sign in with the test account" when needed.

### Edge Cases

- No routes found: generate from goal, product, app type, and local URL.
- Product has little context: ask one extra CLI question for audience or use
  "people evaluating this product" as the default.
- AI returns invalid JSON: retry once with a repair prompt, then fall back to
  the deterministic local checklist.
- AI returns risky actions: parser rejects the guide and the CLI offers the
  deterministic checklist.
- User wants changes: CLI lets them edit step labels before saving.
- Native apps: guide generation still works, but no selectors or browser-only
  advice is allowed.
- Long loading or AI process: generated guide can include a waiting/result step
  so Quick Edit can later treat that timing separately.

### Tests

Required before Phase 3 ships:

- Prompt snapshot tests for web, mobile, auth-required, loading-process, and
  minimal-product inputs.
- Parser tests for malformed JSON, too many steps, empty steps, unsafe steps,
  duplicate IDs, and overlong text.
- Route tests for missing bearer token, wrong product owner, rate limit errors,
  provider failure, invalid provider output, and successful generation.
- CLI command tests or smoke runs for generate, list, show, edit, and make with
  the saved guide.
- End-to-end production smoke: generate guide, save it, record with it, upload,
  and confirm the media job snapshot includes source `ai-assisted`.

## Phase 4: Full AI Agent

### Scope

The first autonomous agent should support web and Expo web only. iOS, Android,
and React Native automation should stay manual until separate mobile-specific
guardrails exist.

The first agent should not create accounts, purchase anything, delete data,
email users, post to social platforms, change billing, or touch real customer
records. It should record a demo using a test account or saved local browser
profile, then stop and ask the user whether to upload.

### Local Architecture

The CLI owns the agent run:

1. Start or connect to the local app.
2. Load the selected guide.
3. Load `.clipstitchr/demo-agent-policy.json`.
4. Open Playwright with the existing persistent browser profile.
5. Confirm auth is ready or ask the user to sign in.
6. Start recording only after preflight passes.
7. For each step, ask the agent planner for the next safe browser action.
8. Check that action against policy before running it.
9. Capture screenshot, URL, action result, and timing.
10. Stop when every guide step is done, max time is reached, or stuck behavior
    is detected.
11. Save the MP4, action log, screenshots, and run summary locally.
12. Show the summary and ask the user to approve upload.

### Policy File

Store policy outside the committed repo by default:

```json
{
  "version": 1,
  "allowedOrigins": ["http://localhost:3000"],
  "allowedRoutes": ["/", "/dashboard", "/dashboard/library"],
  "blockedTextPatterns": [
    "delete",
    "remove account",
    "billing",
    "payment",
    "send email",
    "publish"
  ],
  "allowFileUploads": true,
  "approvedTestValues": {
    "testEmail": "demo@example.com"
  },
  "approvedUploadFiles": [".clipstitchr/samples/demo-sample.mp4"],
  "maxActions": 80,
  "maxRecordingSeconds": 180,
  "stuckStateLimit": 3,
  "requiresApprovalBeforeUpload": true
}
```

The policy should be generated by:

```bash
clipstitchr demo policy init
clipstitchr demo policy check
clipstitchr demo policy edit
clipstitchr demo agent init
```

`clipstitchr demo policy init` shows the safe defaults before saving, and
`clipstitchr demo policy edit` lets users change allowed app URLs, routes,
test values, blocked text, upload files, and limits later. Live app URLs need
explicit approval. Uploads stay disabled unless at least one local file is
approved.
`clipstitchr demo agent init` and `clipstitchr demo agent check` remain legacy
aliases.

The CLI should keep `.clipstitchr/` ignored by Git because policy files can
mention local sample media paths and test-account setup notes.

### Agent Commands

Phase 4 beta commands:

```bash
clipstitchr demo agent init
clipstitchr demo agent check
clipstitchr demo policy init
clipstitchr demo policy check
clipstitchr demo policy edit
clipstitchr demo agent run --guide guide_123
clipstitchr demo agent run --guide guide_123 --dry-run
clipstitchr demo agent export-log agent_run_123
```

`--dry-run` navigates, observes, validates, executes approved local browser
actions, logs evidence, and stops without uploading anything to ClipStitchr. The
normal run should still ask for approval before upload.

### Allowed Browser Actions

The executor should support only a narrow action set:

- `navigate` to an allowed route.
- `click` visible text, role, or label.
- `type` safe demo text into non-sensitive fields, or reusable test values from
  policy when a matching key exists.
- `uploadFile` from an approved local file path.
- `waitFor` visible text, URL, request idle, or a capped timeout.
- `screenshot` for evidence.
- `finishStep` when the observed page matches the guide step.
- `stop` when blocked, done, or unsure.

Every action must be checked by the policy layer before execution. The agent
planner should propose actions, but the policy layer decides what is allowed.

Model-backed planning uses `CLI_DEMO_AGENT_PLANNER_MODEL_ID`, which defaults to
`openai/gpt-5-mini`. The route still consumes planner quota before calling the
provider. Each planner call includes the guide title, guide steps, and user goal
so the next action stays aligned with the requested demo. If the provider call
fails during a CLI run, or if the model repeats an already-attempted action, the
CLI logs the issue once and uses the deterministic local planner for the rest of
that run. If the requested workflow cannot continue because required clips,
selected assets, connected accounts, permissions, or generated results are
missing, the planner can return a stop action with a plain-language reason.

### Stuck Detection

Stop the run when any of these happen:

- Same normalized URL and screenshot fingerprint repeats 3 times.
- Same action fails twice.
- No guide step advances after 10 actions.
- Page leaves the allowed origin.
- Browser shows a sign-in, captcha, permission, or payment wall the policy did
  not approve.
- Max action count or max recording time is reached.

Stopping should save the run summary and ask the user whether to keep the local
MP4. It should not upload automatically after a stuck stop.

### Auth Handling

Supported first:

- Saved Playwright browser profile in `.clipstitchr/browser-profile`.
- Manual user sign-in before recording starts.
- Optional test-account notes in the policy file.

Not supported in the first autonomous release:

- Storing app passwords in ClipStitchr.
- Asking the model to type real secrets.
- Bypassing 2FA, captcha, SSO, or security prompts.
- Recording production accounts without an explicit warning and approval.

### Evidence And Metadata

Each agent run should create:

```text
.clipstitchr/agent-runs/<run-id>/
  action-log.jsonl
  screenshots/
  run-summary.json
  recording.mp4
```

`run-summary.json` should include:

- Guide ID and source.
- Policy file hash.
- Allowed origin and start URL.
- Start and end time.
- Step timings.
- Action counts.
- Stop reason.
- Whether upload was approved.

When the user uploads, include safe summary fields in `walkthrough.agentRun`.
Keep raw screenshots local until a separate upload-and-redaction decision is
made.

### Downloadable Agent Skill

Add this after the internal policy format exists:

```bash
clipstitchr demo guide export-instructions guide_123
```

The export should produce a Markdown instruction file and JSON policy that a
user can paste into Codex, Claude Code, or another local agent. The exported
instructions should say:

- What the demo should show.
- Which routes are allowed.
- Which actions are forbidden.
- When to stop and ask the user.
- How to produce a compatible action log.
- How to hand control back to `clipstitchr demo make --guide <id>`.

This is useful for users who already trust their own local agent, but
ClipStitchr should still treat imported action logs as untrusted data and
validate them before using them for editing decisions.

### Phase 4 Tests

Required before the autonomous agent ships:

- Policy parser tests for allowed routes, blocked words, invalid origins, max
  action bounds, and approved upload paths.
- Guardrail tests that reject external navigation, destructive button text,
  payment pages, production domains, blocked typing, and unapproved file
  uploads. The first CLI-local validator tests now cover external origins,
  disallowed local routes, blocked action text, selector-only clicks, safe demo
  typing, upload approval, approved upload files, and wrong step completion.
- Observer, planner, and executor tests for the guarded action layer. The first
  CLI-local tests now cover simplified visible page observation, screenshot-first
  planning, safe typing, safe clicking, step completion, visible waits, and local
  file upload execution.
- Full-loop tests for a safe multi-step guide flow, blocked observed page text,
  external navigation, disallowed routes, and repeated page state now confirm
  step timings, screenshots, blocked stops, and URL before/after action-log
  details. Auth-wall, modal, long-loading, and 404 page-state fixtures are also
  covered. Time-cap, action-cap, and no-step-progress stops are covered and
  write explicit stop entries.
- Planner parser and injected-planner tests now cover supported JSON actions,
  unsupported action types, selector rejection, approved test-value keys, direct
  safe demo text, and policy rejection before execution.
- `--ai-planner` uses the same action parser and local policy validator after
  the backend returns one model-proposed action, and CLI tests cover fallback to
  the deterministic planner after a provider failure.
- Playwright fixture app tests for dashboard walkthrough, auth-required flow,
  modal flow, long loading flow, stuck loop, 404 route, and external redirect
  are now covered by CLI-local tests. Full-loop file-upload coverage should be
  added before enabling planner-initiated upload flows beyond approved executor
  fixtures.
- Action-log tests that confirm every action has timestamp, step ID, URL,
  result, and stop reason when applicable.
- Upload tests proving the CLI asks for approval before sending any autonomous
  run now cover incomplete runs, `--no-upload`, declined review prompts, and
  approved uploads with safe `walkthrough.agentRun` metadata.
- Redaction tests for screenshots or logs before any future cloud upload.

## Rollout Plan

1. Ship Phase 3 behind explicit `clipstitchr demo guide generate`.
2. Add customer docs only after generation works against production.
3. Keep `clipstitchr demo make` defaulting to manual guided recording.
4. Keep Phase 4 as a private local beta with `clipstitchr demo agent run`.
5. Run GUI smoke checks for the recorded browser path before broad release.
6. Keep upload gated by mandatory local review.
7. Collect failed run summaries from consenting testers, not raw screenshots by
   default.
8. Only then consider adding the agent option to the normal `demo make` prompt.

## Production Ship Checklist

Phase 3 cannot ship until:

- CLI package includes the guide command namespace.
- Web app deploy includes the generation route.
- Convex deploy includes new rate limits and any generated API changes.
- `docs/backend/rate-limits.md` lists the new limit.
- Customer docs explain AI guide generation in plain language.
- Production smoke confirms AI-generated guides upload as `source:
  "ai-assisted"`.
- Npm package is bumped and published.

Phase 4 cannot ship until:

- Policy file, parser, guardrails, dry-run mode, and review-before-upload are
  implemented and tested.
- Fixture app evals pass for safe and blocked scenarios.
- The agent records only web/Expo web targets in the first release.
- Auth handling is documented as saved browser profile or manual test-account
  login.
- Logs and screenshots stay local unless explicit upload/redaction support is
  added.
- Customer docs clearly explain that the autonomous recorder should use a test
  account and avoid destructive flows.

## Known Risks

- AI guide generation can produce vague or risky steps. Strict parsing and user
  review are required.
- Autonomous browser agents can click the wrong thing when UI text changes.
  Policy checks must happen before every action.
- Auth flows can block automation. The first version should ask the user to sign
  in manually and resume.
- Long AI/loading flows can make recordings noisy. Step timings and Quick Edit
  should treat waiting sections separately.
- External agent exports cannot be trusted. Imported logs need the same
  validation as internal agent logs.
